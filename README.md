# バス団子運転 比較シミュレーター

都市部の高頻度バス路線で起きる「団子運転」と、その対策案である「先行バスの降車専用スキップ制御」を比較できる単体Webアプリです。

専門家でない人にも、なぜ団子運転が自然発生するのか、制御によって何が改善し何が悪化するのかを、アニメーション・グラフ・指標で確認できることを目的にしています。

## 実行方法

追加ライブラリやビルドは不要です。

1. このリポジトリを取得します。
2. `index.html` をブラウザで開きます。

Windowsでは次のファイルを直接開けます。

```text
index.html
```

## デフォルト設定の更新

アプリ上部の `設定JSON` で出力したJSON、または結果JSONを使って、初期表示のデフォルト値を更新できます。

```powershell
node tools/apply-default-config.js bus-bunching-config.json
```

このコマンドは `index.html` の `高頻度都市路線` プリセットとフォームの初期値を、JSON内の `config` に合わせて更新します。出力ファイルは `.gitignore` 対象なので、必要な場合だけ別名で保管してください。

## 主な機能

- 制御なし / 制御ありの横並び比較
- 同じ乱数シード・同じ需要条件での再現可能な比較
- 一方向の環状路線モデルを横一直線に展開表示
- バス停、待ち人数、バス位置、乗客数、遅延、混雑、団子発生を可視化
- 距離基準 / 時間基準 / ハイブリッド基準の制御方式切り替え
- 降車専用スキップ制御の発動表示
- 追い越し不可・バース数1固定の前車待ち遅延モデル
- 前車待ち中のバス、詰まっている停留所、停留所占有率の可視化
- プリセット、パラメータ調整、一時停止、リセット、1ステップ実行
- 5シード平均と簡易しきい値スイープ
- JSON / CSV エクスポート
- 設定JSONの出力・読み込み。結果JSONに含まれる `config` からも同じ条件を復元できます。

### 路線・運行条件

| 表示名 | 内部名 | 単位 | 説明 |
| --- | --- | --- | --- |
| バス停数 | `stopCount` | 停留所 | 環状路線上の停留所数です。多いほど路線が長くなり、車間の崩れ方も変わります。入力値は8から28に丸められます。 |
| バス台数 | `busCount` | 台 | 同一路線を走るバスの台数です。多いほど高頻度運行になり、後続車が接近しやすくなります。 |
| 基本速度 | `baseSpeedKmh` | km/h | 停留所間を走る基準速度です。停留所間距離と組み合わせて基準走行時間を決めます。 |
| 停留所間 | `stopDistanceKm` | km | 隣接停留所間の距離です。長いほど走行時間が増え、短いほど停留所での停車時間の影響が強くなります。 |
| 区間平均遅れ | `randomDelayMeanSec` | 秒/区間 | 各区間の走行時間に平均して加わるランダム遅れです。信号機を地図上の固定地点として置くのではなく、区間ごとの信号待ち・交通流の乱れをまとめて、この平均値になるように分布を校正します。 |
| 初期遅延 | `initialDelaySec` | 秒 | 最初の先行バスに任意で与える遅れです。現在の標準値は0秒です。通常は信号・乗客到着などのランダム要因から団子化を発生させます。 |

### 乗客・停車条件

| 表示名 | 内部名 | 単位 | 説明 |
| --- | --- | --- | --- |
| 需要倍率 | `demandMultiplier` | 倍 | 全体の乗客到着率を倍率で調整します。大きいほど停留所に乗客が溜まり、停車時間が伸びます。 |
| 定員 | `capacity` | 人 | バス1台に乗れる最大人数です。定員を超える乗客は停留所に残り、満員通過として集計されます。 |
| 乗車 | `boardTimeSec` | 秒/人 | 中ほどのドアから乗車する乗客1人あたりの処理時間です。現在の標準値は3秒/人です。 |
| 降車 | `alightTimeSec` | 秒/人 | 前方ドアから降車する乗客1人あたりの処理時間です。現在の標準値は2.8秒/人です。 |
| 混雑時 固定追加秒 | `crowdedExtraSec` | 秒 | 車内混雑率がしきい値以上の場合、乗車処理と降車処理それぞれの固定時間に追加する秒数です。現在の標準値は5秒です。 |
| 減速・加速ロス | `stopManeuverLossSec` | 秒/停車 | 停留所へ寄せる減速、発進、交通流へ戻る時間を表す停車ごとのロスです。現在の標準値は10秒です。 |
| ドア開閉 | `doorTimeSec` | 秒/停車 | ドア開閉と客扱い開始・終了の基本時間です。現在の標準値は3秒です。 |
| 乗車発生時 固定秒 | `boardingSetupSec` | 秒 | 乗車客がいる場合だけ追加される固定時間です。現在の標準値は3.5秒です。 |
| 降車発生時 固定秒 | `alightingSetupSec` | 秒 | 降車客がいる場合だけ追加される固定時間です。現在の標準値は3.5秒です。 |
| 混雑判定しきい値 | `crowdingThreshold` | 0から1 | 車内混雑率がこの値以上のとき、混雑時固定追加秒を乗車・降車の各処理に加えます。現在の標準値は0.8です。 |
| 重要・集中停留所 | `hotspotStops` | 停留所番号 | 需要が集中し、目的地にもなりやすい停留所番号のカンマ区切りリストです。例: `3,4`。駅、病院、学校、乗換拠点などを想定します。 |
| 重要停留所スキップ禁止 | `protectHotspotStops` / `forbiddenStops` | なし | 有効にすると、重要・集中停留所では降車専用スキップを発動しません。現在の標準値は無効です。 |
| 集中倍率 | `hotspotMultiplier` | 倍 | 重要・集中停留所の乗客到着率に掛ける倍率です。 |

### 停車時間の式

停車時間は、単純な「基本停車5秒 + 乗降人数」ではなく、停車前後の速度低下と、ドア開閉、乗車・降車処理を分けて計算します。このモデルでは、中ほどのドアから乗車し、前方ドアから降車しますが、車内の交通整理のため乗車と降車は同時にはできない前提です。

```text
停車時間 =
  減速・加速ロス
  + ドア開閉時間
  + 降車処理時間
  + 乗車処理時間

乗車処理時間 =
  乗車人数 > 0 のとき 乗車発生時固定秒 + 混雑時固定追加秒 + 乗車人数 × 乗車秒/人
  乗車人数 = 0 のとき 0

降車処理時間 =
  降車人数 > 0 のとき 降車発生時固定秒 + 混雑時固定追加秒 + 降車人数 × 降車秒/人
  降車人数 = 0 のとき 0
```

混雑時固定追加秒は、車内混雑率が混雑判定しきい値以上の場合だけ加算します。乗車と降車が両方ある場合は、それぞれの固定時間に追加されます。

降車専用スキップ時は、降車客がいなければ完全通過で0秒、降車客がいれば減速・加速ロス、ドア開閉、降車処理時間だけを計上します。

### 降車専用スキップ制御

| 表示名 | 内部名 | 単位 | 説明 |
| --- | --- | --- | --- |
| 制御方式 | `policyMode` | なし | スキップ発動の判定方式です。`distance` は距離基準のみ、`time` は時間基準のみ、`hybrid` は距離と時間の両方を満たす場合に発動します。 |
| 後続車間しきい値 | `distanceThresholdStops` | 停留所数 | 後続バスが何停留所以内まで近づいたら制御候補にするかです。小さいほど保守的、大きいほど発動しやすくなります。 |
| 後続到着しきい値 | `timeThresholdMin` | 分 | 後続バスが対象停留所に何分以内に到着見込みなら制御候補にするかです。 |
| 先行遅延しきい値 | `delayThresholdMin` | 分 | 先行バスがこの遅延以上のときだけスキップ制御を検討します。定時または軽微な遅れのバスまで乗車拒否しないための安全弁です。純粋な車間制御だけを見たい場合は0にできます。 |
| 後続混雑率しきい値 | `followerLoadLimit` | 0から1 | 後続バスの混雑率がこの値を超える場合、後続に乗客を任せるのは危険としてスキップを禁止します。 |

先行遅延しきい値は必須ではありません。ただし、距離または時間基準だけだと、先行バスがほぼ定時でも後続が近いという理由だけでスキップが発動します。これは利用者説明上かなり厳しいため、政策検討用の標準設定では残しています。

### 内部固定パラメータ

| 内部名 | 値 | 説明 |
| --- | --- | --- |
| `sampleIntervalSec` | 15秒 | 指標の時系列履歴を記録する間隔です。グラフのサンプリング間隔になります。 |
| `arrivalQuantumSec` | 5秒 | 乗客到着イベントを生成する時間刻みです。 |
| `noiseBucketSec` | 60秒 | 区間走行遅れを共有する時間幅です。同じ停留所間に同じ時間帯で入ったバスは同じ信号・交通流の乱れを受けます。 |
| `baseRatePerMin` | `0.23 * demandMultiplier` | 各停留所の基本乗客到着率です。停留所位置、時間帯波形、集中倍率でさらに補正されます。 |
| `wave` | 時間帯需要係数 | シミュレーション中盤で需要がやや高くなるようにする内部係数です。 |
| `centerBias` | 停留所位置係数 | 路線中央付近の需要をやや高くする内部係数です。 |
| `travelNoise` | 乱数生成 | 停留所間の走行時間に、信号・渋滞・まれな大きめの遅れを加える処理です。UIの `randomDelayMeanSec` が1区間あたりの平均追加遅れになるように内部スケールへ変換します。 |

`travelNoise` は、平均0の走行揺らぎ、通常の小さめの遅れ、まれな大きめの詰まりを合成します。内部スケール `R` は `randomDelayMeanSec / 0.2456` で計算し、期待値がUIで指定した `randomDelayMeanSec` になるようにしています。

### 値を変えたときの読み方

- 団子運転を起こしやすくするには、`demandMultiplier`、`boardTimeSec`、`stopManeuverLossSec`、`randomDelayMeanSec`、`initialDelaySec` を上げます。
- 高頻度都市路線に近づけるには、`busCount` を増やし、`stopDistanceKm` を短めにします。
- 低頻度郊外路線に近づけるには、`busCount` を減らし、`stopDistanceKm` を長めにします。
- スキップ制御を発動しやすくするには、`distanceThresholdStops` と `timeThresholdMin` を上げ、`delayThresholdMin` を下げ、`followerLoadLimit` を上げます。
- 副作用を抑えるには、`followerLoadLimit` を厳しめにし、必要に応じて `protectHotspotStops` を有効にします。
- 前車待ちを強く見たい場合は、需要や乗降時間を上げ、バス台数を増やします。

## シミュレーションモデル

このアプリは教育・議論用の簡略モデルです。

- 乗客は時間経過で各停留所にランダム到着します。
- 乗客は下流側の目的地を持ちます。
- バスは環状路線を一方向に走行します。
- バスは停留所以外の区間でも追い越し不可です。内部ではバスごとの累積走行位置 `routePos` を持ち、移動量を計算する時点で先行車の直後までしか進めないようにしています。
- 停留所では乗車人数・降車人数に応じて停車時間が増えます。
- 降車客がなく、停留所の待ち客も0人の場合、その停留所は通過し、停車時間は0秒です。
- バスには定員があります。
- 走行時間には信号・渋滞を表すランダム遅延があります。
- 遅れたバスほど停留所で待つ乗客が増え、停車時間が伸びます。
- 後続バスは乗客が少なく停車時間が短くなり、先行バスに追いつきやすくなります。
- 各停留所はバース数1固定で、追い越し不可です。
- 前のバスが客扱い中の場合、後続バスは停留所手前で待機します。

乗客の目的地は、乗車停留所より下流側の停留所から乱数で決めます。同じ停留所を目的地にはせず、環状路線上で1停留所以上先に進む目的地になります。現在は実測ODではなく、比較的短距離から中距離の移動が多くなる簡略分布ですが、重要・集中停留所は駅・乗換拠点のように降車目的地にもなりやすいよう、目的地選択の重みを高くしています。

## 降車専用スキップ制御

制御ありモードでは、先行バスが停留所に到着したとき、条件を満たす場合にその停留所を「降車のみ扱い」にします。

主な判定条件:

- 先行バスが一定以上遅延している
- 後続バスが一定距離以内、または一定時間以内に到着見込み
- 後続バスが混雑しすぎていない
- 重要停留所スキップ禁止が有効な場合、対象停留所が重要・集中停留所ではない

乗車を見送られた乗客は停留所に残り、後続バスを待ちます。

## 参考にした停車時間モデル

- TCRP Report 165 / Transit Capacity and Quality of Service Manual, Third Edition, Chapter 6: Bus Transit Capacity
- TCRP Report 100 / Transit Capacity and Quality of Service Manual, 2nd Edition, Part 4: Bus Transit Capacity

本アプリの停車時間式は、これらで示されるドア開閉時間、乗降処理時間、停留所での加減速ロスの考え方を簡略化して使っています。現在の運用前提では、車内交通整理のため乗車と降車を同時に扱わず、降車処理と乗車処理を逐次加算します。標準値は、乗車3秒/人、降車2.8秒/人、乗車固定3.5秒、降車固定3.5秒、混雑時固定追加5秒、ドア開閉3秒を基準にしています。
