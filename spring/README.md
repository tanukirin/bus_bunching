# バス団子運転 3方式比較シミュレーター

このサブアプリは、同じ乱数シード・同じ需要イベントで次の3方式を同時に比較する教育・検証用ツールです。

- `plain`: 制御なし
- `skip`: 距離基準スキップ制御
- `spring`: スプリング法

ルート直下の既存アプリを基準版として残し、このディレクトリでは3方式比較に特化しています。実行方法は `spring/index.html` をブラウザで開くだけです。

デフォルト値の更新ツールは第2引数で対象HTMLを指定すると、この3方式版にも使えます。

```powershell
node tools/apply-default-config.js bus-bunching-config.json spring/index.html
```

## 3方式の違い

制御なしは、乗客発生、停車時間、走行遅れ、前車待ちだけで団子運転がどう発生するかを見る基準です。

スキップ制御は距離基準のみです。対象バスの後続が `後続車間しきい値` 以内にいる場合だけ、先行遅延、後続混雑率、重要停留所保護などの安全弁を満たせば、停留所を降車専用扱いにして待客を後続へ任せます。`time` / `hybrid` 判定はこの3方式版では使いません。

スプリング法は、停留所保持と補助スキップだけで車間を整えます。速度調整や巡航速度補正は入れていません。保持は前方に詰まり、後方に空白があるときに自車を停留所で待たせます。補助スキップは前が空き、後ろが近いときだけ、既存のスキップ安全弁と headway cost 改善チェックを満たす場合に使います。

## 進行方向と車間

方向定義は常に次の向きです。

```text
進行方向 →

後方バス        自車          前方バス
   A ----------- B ------------ C
        h_back        h_front
```

- `h_back`: 後方バスAから自車Bまでの間隔
- `h_front`: 自車Bから前方バスCまでの間隔
- `idealHeadway`: 理想車間。基本的に `stopCount / busCount`
- `springSignal = h_front - h_back`

`springSignal > 0` は前が空いて後ろが近い状態なので、自車Bを前へ進めたい状態です。`springSignal < 0` は前が近く後ろが空いている状態なので、自車Bを前へ逃がしたくない状態です。

## スプリング保持と補助スキップ

保持は次の条件を基本に発動します。

```text
h_front < idealHeadway
かつ
h_back > idealHeadway
```

保持秒は `スプリングゲイン`、`スプリング不感帯`、`springDamping`、`最大保持秒` で制限されます。保持中のバスは路線図上で「スプリング保持」と表示されます。

補助スキップは次の条件を基本に候補化します。

```text
h_front > idealHeadway
かつ
h_back < idealHeadway
```

さらに、重要停留所保護、先行遅延しきい値、後続混雑率しきい値、headway cost 改善チェックを満たす必要があります。

## 指標の読み方

- `最小車間`: 小さいほど団子がひどい状態です。
- `最大車間`: 大きいほど空白区間がひどい状態です。
- `headway RMSE`: 理想車間からのずれの大きさです。小さいほど全体として等間隔です。
- `平均総所要時間` / `95%総所要時間`: 乗客が停留所で待ち始めてから目的地で降車するまでの時間です。待ち時間、乗車後の移動、前車待ち、スプリング保持、スキップによる影響を含む利用者目線の総合指標です。未降車の乗客は含めません。
- `直近5分待ち時間`: 直近5分に乗車した乗客の待ち時間です。目的地での降車前でも、乗車済みなら集計対象にします。該当乗客がいない時点は0ではなくデータ無しとして扱い、シード平均では値があるシードだけを平均します。
- `スキップ人数` / `追加待ち`: スキップ制御と補助スキップが乗客に与えた直接負担です。
- `スプリング保持累積`: スプリング法がどれだけバスを停留所に保持したかを示します。多すぎる場合は待ち時間悪化や停留所占有の副作用に注意します。

## 追加パラメータ

- `springGainSecPerStop`: 負の `springSignal` を保持秒へ変換する強さ
- `springDeadbandStops`: 小さな車間差では介入しない不感帯
- `springDamping`: 既に遅れているバスへの追加保持を弱める係数
- `springMaxHoldSec`: 1回あたり最大保持秒
- `springMinHoldSec`: 短すぎて現実的に扱いにくい保持を抑える最小保持秒

## モデルの限界

このシミュレーターは教育・議論・仮説検証用の簡略モデルです。実在路線の運行計画や施策判断には、実測OD、停留所別乗降、信号・道路条件、運行管理ルール、利用者影響の検証が必要です。スプリング法も速度調整なしの停留所保持＋補助スキップとして単純化しています。
